# アーキテクチャ

```
main.cpp
  └─ App (src/app.cpp)                アプリ状態機械 + タッチ UI
       ├─ ISampler                    取り込みエンジン抽象
       │    ├─ SamplerParlio          PARLIO RX + GDMA
       │    └─ SamplerCpu             GPIO ポーリングループ
       ├─ CaptureBuffer               PSRAM のサンプル列 + LOD ピラミッド
       ├─ findTrigger()               トリガ条件のソフトウェア検索
       ├─ measureChannels()           ch ごとの周波数/デューティ/エッジ
       ├─ runDecoder()                UART / I2C / SPI
       ├─ WaveformView                波形・ルーラ・注釈・カーソルの描画
       └─ Exporter                    microSD への CSV / VCD / txt / BMP
```

## サンプル格納形式

1 サンプル 1 バイト。ビット N が ch N です。8ch を 1 バイトに詰めることで

- PARLIO の `data_width = 8` とそのまま一致する
- CPU エンジンのパック処理が数命令で済む
- トリガ検索・測定・デコードがすべて「バイト列の走査」になる

という形に揃えました。深度 8 MSa でも 8 MB なので、Tab5 の 32 MB PSRAM に
余裕で収まります。

## サンプリングエンジン

### PARLIO (高速・DMA)

ESP32-P4 の PARLIO 受信器は、内部で分周したクロックの各エッジで 8 本の入力を
ラッチし、GDMA でメモリに書き出します。CPU は一切関与しないのでジッタが
ありません。

設計上のいちばんの制約は、ドライバが **内部 RAM 以外のペイロードを拒否する**
ことです (`parlio_rx_unit_receive()` の `esp_ptr_internal()` チェック)。
`indirect_mount` を使えば PSRAM を渡せますが、その場合ドライバが同じサイズの
内部バッファを確保するので結局内部 RAM を食います。さらに soft delimiter の
EOF 長レジスタは 16 bit しかなく、1 トランザクションは 64 KiB までです。

そこで、

1. 内部 RAM に 65280 バイト (= 0xFF00、64 バイト境界かつ EOF 長の上限内) の
   リングを確保する
2. `partial_rx_en = true` の **無限トランザクション** を張る。ディスクリプタ
   チェーンが循環するので、ハードウェアはブロック間で一度も止まらない
3. ディスクリプタ完了ごとに呼ばれる `on_partial_receive` から PSRAM へ
   memcpy し、目標サンプル数に達したらセマフォで起こす

という構成にしました。リングは 16 個のディスクリプタに分かれるため、
20 MSa/s でもコールバックは 200 µs に 1 回、コピーは 4 KiB ずつです。
書き手に追いつけなくなる余裕はほとんどありません。

レートはハードウェア分周器が 160 MHz を整数分周するため、要求値ちょうどには
なりません。UI には丸めた後の値を出しています。

### CPU (汎用フォールバック)

`GPIO_IN_REG` / `GPIO_IN1_REG` を直接読み、config.h のピンマップから
コンパイル時に展開したシフト列で 1 バイトに詰めます。既定のピンマップは
全 ch がバンク 0 なので、レジスタ読みは 1 回だけです。

ペーシングはディレイループではなく RISC-V のサイクルカウンタで行います。
サンプルごとに締切を計算して、そこまでスピンします。要求レートがループの
限界より速い場合は締切が常に過去になるので自然にフリーランに落ち、
**実測レート** を返します。時間軸が嘘にならないのがこの方式の利点です。

割り込みは 2 ms 程度のチャンク単位でマスクします。数秒かかる取り込みの間
ずっとマスクすると tick とウォッチドッグが死ぬので、チャンク境界に小さな
(報告済みの) 隙間ができることを受け入れています。

## トリガ

ハードウェアトリガは無いので、**バッファを埋めてから条件を探す** 方式です。

- エッジ条件 (Rise / Fall / Both) は互いに OR
- レベル条件 (High / Low) は互いに AND
- 両方あるときは「いずれかのエッジ AND すべてのレベル」

`TriggerConfig` は `compileTrigger()` で 4 つのビットマスクに畳まれるので、
検索ループは 1 サンプルあたり数命令で済みます。

検索はプリトリガ分だけ進んだ位置から始めます。こうすると、見つかった位置の
手前に必ず要求されたプリトリガ長が確保されます。

NORMAL モードは見つからなければタイムアウトまで取り込みをやり直します。
連続波形には十分ですが、単発の稀なイベントは取り逃す可能性があります。
これは「取り込み中は 1 サンプルも落とさない」ことを優先したトレードオフです。

## 描画: LOD ピラミッド

8 MSa を 1150 px に描くと 1 列あたり 7000 サンプル。毎フレーム全走査すると
PSRAM 帯域で数百 ms かかります。かといって間引くと 1 サンプルのグリッチが
見えなくなり、ロジックアナライザーとして使い物になりません。

そこで取り込み完了時に **(OR, AND) の要約ピラミッド** を作ります。

- レベル 0 は 64 サンプルを 1 エントリに畳む
- 以降は 2 エントリずつ畳んで倍々

OR は「一度でも High だったか」、AND は「ずっと High だったか」を表すので、
どれだけズームアウトしても 1 サンプルの尖りが「High と Low の両方あり」=
縦線として残ります。**正確さを落とさない間引き** です。

メモリは 2 バイト x (N/64) x 2 ≒ N/16 バイト。8 MSa でも 512 KB 程度です。

1 px あたり 1 サンプル未満まで拡大したときは、ピラミッドを使わず実サンプルを
そのまま階段状に描きます。

## デコーダ

すべてのデコーダは `AnnotationList` (PSRAM 上の固定長配列) に
`{開始サンプル, 終了サンプル, 種別, 行, 文字列}` を積みます。波形ビューも
テキスト出力もこの 1 種類だけ見ればよく、プロトコルを増やしても表示側は
変わりません。サンプル順に積まれるので、表示範囲の頭出しは二分探索です。

- **UART**: 立ち下がりを開始ビットとみなし、各ビットセルの中央を読みます。
  オートボーは「観測された最小パルス幅 = 1 ビット」から求めます。ストップ
  ビットが High でなければフレーミングエラーとして報告し、ビットクロックを
  信用せず次のエッジで同期を取り直します。
- **I2C**: SCL が High の間の SDA 遷移を START / STOP、SCL 立ち上がりで
  データをサンプル、9 ビット目を ACK/NAK として扱います。
- **SPI**: CPOL/CPHA からサンプルエッジを決め、CS (省略可) でワード境界を
  リセットします。MOSI と MISO を別の行に出します。

## エクスポート

- **CSV** は表示範囲のみ、1 サンプル 1 行。全体を出すと数十 MB になるためです。
- **VCD** は全体ですが値の変化点だけ書くので小さく収まります。タイムスケールは
  「1 サンプルあたり 10 ステップ以上」を保つ最も粗い単位を自動で選びます。
  PulseView や GTKWave でそのまま開けます。
- **BMP** は 24 bit 無圧縮。`readRect()` で 1 行ずつ読んで書き出します。
