    概述

    把 M5Stack Tab5（ESP32-P4）变成 8 通道逻辑分析仪的固件。采集、触发、波形浏览、协议解码以及导出到 microSD，全部在 5 英寸触摸屏上完成，不需要连接电脑。

    功能概要

    80 MSa/s

    使用 PARLIO + DMA 实测得到的最高采样率，8 通道同时。

    8 MSa

    PSRAM 中的最大采集深度。每个采样点占 1 字节。

    3 种

    内置 UART / I2C / SPI 协议解码器。

    0.00%

    对 1 MHz 基准信号的频率测量误差（实测）。

    项目内容
    采集8 通道，深度 64 kSa – 8 MSa，速率 100 kSa/s – 80 MSa/s
    采集引擎PARLIO（DMA，高速）与 CPU（轮询，后备），自动选择
    触发每通道 Rise / Fall / Both / High / Low。边沿之间取或，电平之间取与。预触发 0–95%
    显示双指缩放、拖动平移；采用 LOD 渲染，缩小后单个采样点的毛刺依然可见
    测量每通道的频率、占空比、边沿数、最小高/低电平脉宽
    解码器UART（支持自动波特率）、I2C、SPI
    导出CSV（当前视图）、VCD（整段采集，可用 PulseView 与 GTKWave 打开）、解码结果、屏幕 BMP
    远程控制基于 USB CDC 的行式 JSON API

    与廉价逻辑分析仪的对比

    几十元级别的 FX2LP（CY7C68013A）逻辑分析仪标称 8 通道 24 MSa/s。实测对比如下。

    FX2LP 类产品本项目
    通道数88
    最高速率24 MSa/s（标称）80 MSa/s（实测）
    采集深度通过 USB 流式传输，取决于主机机内 8 MSa
    显示必须配合电脑软件机身独立完成
    解码器sigrok 的完整解码器集合UART / I2C / SPI

    在解码器种类上远不及 sigrok。导出 VCD 后可以用 PulseView 打开，因此「用本机抓取、到电脑上分析」是很实际的分工。

    限制

    • 输入仅支持 3.3V 逻辑电平。不加分压或电平转换直接接入更高电压会损坏 ESP32-P4。
    • 触发是软件搜索。先填满缓冲区再查找条件，因此极少出现的单次事件有可能错过。
    • 采样率只能是 160 MHz 的整数分频，即 80 / 53.33 / 40 / 32 / 26.67 / 22.86 / 20 MSa/s 等。
    • 只能测量数字电平，无法进行模拟测量。

    安装与接线

    探头接线、编译与烧录。

    探头接线

    探头接到 Tab5 的 M5-Bus 排针（2×15，30 针）上。

    通道GPIOM5-Bus 引脚备注
    CH0G221通用 GPIO
    CH1G319通用 GPIO
    CH2G420通用 GPIO
    CH3G511与 M5-Bus SPI_SCK 共用
    CH4G162通用 GPIO
    CH5G174与 M5-Bus PB_IN 共用
    CH6G187与 M5-Bus SPI_MOSI 共用
    CH7G199与 M5-Bus SPI_MISO 共用
    GND—1 / 3 / 5必须与被测电路共地

    输入为 3.3V。直接接入 5V 或 12V 信号会烧毁 ESP32-P4。测量更高电压时请使用分压电路或 3.3V 电平转换/缓冲器。

    第 25 / 27 / 29 针为 HVIN，第 28 / 30 针为 5V 与电池。请注意不要让探头引线碰到它们。

    空闲输入默认启用内部上拉，因此未连接的通道会稳定读为高电平，而不会拾取噪声。

    8 个引脚全部位于 GPIO bank 0（GPIO0–31），因此 CPU 引擎只需一次寄存器读取即可获得全部通道。如果要重新分配引脚，尽量不要跨 bank，否则吞吐会下降。映射位于 include/config.h 开头几行。

    不接线的首次验证

    内置测试信号发生器可以在不接任何线的情况下验证整条通路。通过远程控制 API：

    gen ch=0 freq=1000000 duty=50
trigger clear=1
config engine=parlio rate=26666666 depth=2097152
single

    采集结束后发送 stats。若 stats[0].freq 接近 1000000，说明 GPIO 矩阵、PARLIO、DMA 与缓冲区都工作正常。

    右上角的状态显示

    形如 CPU TRIG'D @ 5.000 MHz #2。

    • 引擎 — 实际使用的采集引擎（PARLIO 或 CPU）
    • 状态 — IDLE / SAMPLING / TRIG'D（已触发）/ UNTRIG（未触发）/ FAILED
    • @ 速率 — 实际有效采样率，是硬件真正产生的值而非请求值
    • #n — 采集次数

    如何读测量值

    中部面板的 MEASUREMENTS 是针对整段采集的各通道统计。

    • 频率 — 由上升沿平均间隔算出，不会被窗口边缘被截断的脉冲串带偏
    • 占空比 — 仅统计完整周期内的平均高电平比例
    • 边沿数 — 整段采集中的跳变次数
    • 非周期信号会显示 N edges min 120 ns，即观测到的最窄脉宽

    最小脉宽可以用来判断采样率是否够用：如果它只有采样周期的 2–3 倍，就应该提高采样率。

    采集与触发

    采样率与深度的选择，以及触发条件的组合方式。

    采样率与深度

    对于关心的最快边沿，采样率取其 5–10 倍为宜。采集时间为 深度 ÷ 采样率，显示在中部面板的 window 处。

    操作作用
    速率 - +100 kSa/s – 80 MSa/s。实际值请看状态显示中 @ 后的数字
    深度 - +64 kSa – 8 MSa。改变深度会丢弃当前采集，改变速率则不会
    ENGAUTO / PARLIO / CPU。AUTO 会优先选择可用的 PARLIO

    采样率只能是 160 MHz 的整数分频，菜单中只列出实际可达的值（80 / 53.33 / 40 / 32 / 26.67 / 22.86 / 20 MSa/s …）。无法输出正好 24 MSa/s，请使用略高的 26.67 MSa/s。

    触发条件

    • 每点击一次通道按钮，条件依次切换 -- → Rise → Fall → Both → High → Low → --。
    • 边沿条件之间取或，电平条件之间取与；两者同时存在时为「任一边沿 且 所有电平」。
    • 例如 CH0=Rise、CH1=Low 表示「CH1 为低电平期间 CH0 出现上升沿」。
    • pre % 是预触发比例。设为 25% 时屏幕左侧 1/4 为触发前的数据。
    • Clear all 将所有通道恢复为 --。没有任何条件时相当于不触发，直接显示采到的数据。

    触发模式

    模式找不到条件时
    AUTO照样显示
    NORMAL在 5 秒内反复采集并查找，期间保留上一次的画面
    SINGLE只采集一次然后停止

    触发是软件搜索而非硬件比较器。先填满缓冲区再扫描，因此 NORMAL 模式是「采集 → 查找 → 未找到则重新采集」的循环。对周期性信号足够用，但极少出现的单次事件有可能落在两次采集之间。这是为了保证「采集过程中一个采样点都不丢」而做出的取舍。

    采集后为什么不是显示全体

    把整段采集塞进波形区，意味着用大约 1180 像素画 2 MSa，即每列约 1700 个采样点。这样所有通道都会变成实心色块，完全看不出信号形状。

    因此采集完成后会根据数据自动选择缩放：让各通道最小脉宽的中位数约占 3 个像素。之所以取中位数而不是最小值，是因为当快速的 SPI 时钟与低速 UART 混在一起时，按最小值会放大过度，其余通道全部变成直线。想看全局时按 Fit，想回到自动缩放时按 Auto。

    为什么缩小后毛刺不会消失

    如果简单地把 8 MSa 抽取到约 1150 列，单个采样点的毛刺就会消失，逻辑分析仪也就失去了意义。

    因此每次采集完成后都会构建 (OR, AND) 摘要金字塔。OR 表示「是否曾经为高」，AND 表示「是否始终为高」，所以无论缩小多少，单个采样点的尖峰仍会以「同时存在高与低」的形式显示为一条竖线。这是不损失信息的抽取。

    协议解码

    在波形下方叠加显示 UART / I2C / SPI 的解码结果。

    I2C

    只需分配 SCL 与 SDA 两个通道。上行显示 START / Sr（重复起始）/ STOP、带 R/W 位的地址以及数据字节。

    UART

    项目说明
    Line信号所在通道
    Baudauto 或固定值。auto 会把观测到的最窄脉冲当作 1 个比特来推算
    Data bits5–9
    ParityN / E / O
    Stop bits1 或 2
    Polarity普通 TTL 串口为 idle high；使用反相探头时选 inverted
    Bit order通常为 LSB first

    停止位不为高的帧会以红色标为 T!，该字节也用错误色显示。此时解码器不再信任位时钟，而是在下一个边沿重新同步，因此一个坏字节不会破坏整条数据流。

    自动波特率的前提是至少存在一个 1 比特宽的脉冲。全是 0x00 或 0xFF 的数据流会推算错误，这时请指定固定波特率。

    SPI

    CLK 为必填，MOSI / MISO / CS 可用 -- 关闭。CS 设为 -- 时视为始终选中。采样边沿由 CPOL / CPHA 决定（CPOL 等于 CPHA 时在上升沿采样）。

    用 PulseView / GTKWave 打开

    1. 把 VCD 复制到电脑
    2. 在 PulseView 中选择 Import Value Change Dump data
    3. 随后即可使用 sigrok 丰富的解码器

    时间刻度会自动选取「每个采样点至少 10 个刻度」条件下最粗的单位，因此改变采样率也不会损失分辨率。

    远程控制 API

    用于烧录的 USB CDC 端口同时也是行式控制 API：发送一行，返回一行 JSON。

    请勿操作 DTR / RTS。在 ESP32 的 USB-Serial-JTAG 上，这两根线直接连到复位与启动引脚，翻转它们会使开发板进入 ROM 引导程序并停止响应。打开串口时请让两者保持 false。

    日志输出已经调低，但 ESP-IDF 在启动时仍会输出几行。请忽略所有不以 { 开头的行。

    命令在两次采集之间处理。采集期间会阻塞，因此在扫描途中发送的 stop 会在下一次扫描前生效。

    解码器

    decode kind=i2c scl=0 sda=1
decode kind=uart line=2 baud=auto bits=8 parity=n stop=1
decode kind=spi clk=4 mosi=5 miso=6 cs=7 cpol=0 cpha=0 order=msb bits=8

    任何改动都会触发重新解码。mosi / miso / cs 可以设为 -1 以关闭该通道。

    内置测试信号发生器

    gen ch=N [freq=Hz] [duty=0..100] 会用 LEDC 驱动该通道的引脚，同时仍然对其采样，因此不接任何线也能验证整条通路。

    gen pin=<gpio> 可以驱动任意 GPIO。把空闲引脚（例如 G47 = M5-Bus 第 23 针）用跳线直接接到某个测量通道，就能连外部路径一起验证——焊盘、真实导线、焊盘。最多可同时驱动 4 个引脚。

    > gen ch=0 freq=1000000 duty=50
{"ok":true,"gen":"on","ch":0,"pin":2,"freq":1000000,"duty":50,"res_bits":5}
> gen off=1

    res_bits 是 LEDC 的分辨率，频率越高该值越小。占空比的量化步长为 1/2res_bits，因此高频时无法得到正好 50%（res_bits=5 时为 15/32 = 46.9%）。

    PowerShell 辅助脚本

    $p = New-Object System.IO.Ports.SerialPort "COM6",115200,None,8,one
$p.DtrEnable = $false   # 必须：翻转会使开发板进入引导程序
$p.RtsEnable = $false
$p.NewLine = "`n"
$p.Open()

function Send-Cmd([string]$c) {
  $p.WriteLine($c)
  $sb = New-Object System.Text.StringBuilder
  $deadline = (Get-Date).AddSeconds(15)
  while ((Get-Date) -lt $deadline) {
    $null = $sb.Append($p.ReadExisting())
    foreach ($ln in ($sb.ToString() -split "`n")) {
      $t = $ln.Trim()
      if ($t.StartsWith('{') -and $t.EndsWith('}')) { return $t | ConvertFrom-Json }
    }
    Start-Sleep -Milliseconds 15
  }
}

    架构

    采集引擎、触发与渲染的设计及其理由。

    main.cpp
  └─ App                            应用状态机 + 触摸 UI
       ├─ ISampler                  采集引擎抽象
       │    ├─ SamplerParlio        PARLIO RX + GDMA
       │    └─ SamplerCpu           GPIO 轮询循环
       ├─ CaptureBuffer             PSRAM 采样存储 + LOD 金字塔
       ├─ findTrigger()             触发条件的软件搜索
       ├─ measureChannels()          各通道频率/占空比/边沿

       ├─ WaveformView               波形、标尺、标注、光标
       └─ Exporter                   microSD 上的 CSV / VCD / txt / BMP

    采样存储格式

    每个采样占 1 字节，bit N 对应通道 N。把 8 个通道压进 1 字节的好处是

    • 正好与 PARLIO 的 data_width = 8 对应；
    • CPU 引擎的位重排只需几条指令；
    • 触发搜索、测量与解码全都变成对字节数组的扫描。

    即使深度为 8 MSa 也只有 8 MB，Tab5 的 32 MB PSRAM 绰绰有余。

    PARLIO 引擎

    ESP32-P4 的 PARLIO 接收器在内部分频时钟的每个边沿锁存 8 路输入，并通过 GDMA 写入内存。全程不占用 CPU，因此没有抖动。

    设计上最大的约束是驱动拒绝位于内部 RAM 之外的 DMA 载荷。因此在内部 RAM 中开辟 191 KiB 的环形缓冲区，并挂上 partial_rx_en 的无限事务。由于描述符链是循环的，硬件在块之间一次都不会停顿。

    数据如何离开这个环形缓冲区，决定了可达到的采样率。

    模式条件特点
    direct深度 ≤ 191 kSa采集期间完全不复制，没有任何实时约束，速率仅受外设本身限制
    stream深度 > 191 kSa每个描述符完成时在中断中复制到 PSRAM，复制必须跟得上采样率

    CPU 引擎

    直接读取 GPIO 输入寄存器，并用编译期从 config.h 的引脚映射展开的移位序列压成 1 字节。默认映射下所有通道都在 bank 0，因此只需一次寄存器读取。

    节拍控制不使用延时循环，而是用 RISC-V 的周期计数器：为每个采样计算截止时刻并自旋等待。当请求速率超过循环极限时，截止时刻总在过去，循环自然进入自由运行，并返回实测速率。这正是时间轴不会说谎的原因。

    中断以约 2 ms 为单位分段屏蔽。若在长达数秒的采集中始终屏蔽，时钟节拍与看门狗都会失效，因此接受在分段边界出现一个很小的（并已报告的）间隙。

    触发

    没有硬件触发，因此采用先填满缓冲区再查找条件的方式。TriggerConfig 会折叠成 4 个位掩码（上升 / 下降 / 高电平 / 低电平），使搜索循环每个采样只需几条指令。

    搜索从预触发长度之后的位置开始，这样可以保证找到的位置之前一定有所要求的预触发长度。

    渲染与闪烁

    Tab5 的 MIPI-DSI 面板只有一块帧缓冲（M5GFX 以 num_fbs = 1 配置），并且被持续扫描输出。也就是说直接画到屏幕上的内容会立刻可见，包括「清除某个区域」与「重新绘制」之间的那一瞬间，这正是闪烁的来源。

    为此做了三件事。

    • 波形离屏合成 —— 先画到 PSRAM 中的 M5Canvas（1184×454×2，约 1.03 MB），再一次性推送，中间状态不会出现在屏幕上。
    • 按列渲染 —— 不再「先清空整个绘图区、再逐通道绘制」，而是把每一列的背景、网格线、通道分隔线与全部 8 条波形一起画出。附带的好处是 LOD 金字塔的查询次数变成了原来的八分之一（此前同一列范围会被逐通道查询 8 次）。
    • 外框增量更新 —— 只重绘外观发生变化的按钮，测量值只清除自身字段的尾部。整个界面中不再有任何整块 fillRect 清除。

    这些都不会与采集争抢资源。绘制只在两次采集之间运行（主循环是单线程），因此推送不会与 DMA 或复制中断争夺 PSRAM 带宽。

    LOD 金字塔

    采集完成时构建 (OR, AND) 摘要金字塔。第 0 层把 64 个采样折叠为 1 项，之后每层再折半。内存开销为 2 字节 × (N/64) × 2 ≈ N/16 字节，即使 8 MSa 也只有约 512 KB。

    放大到每像素不足 1 个采样时则绕过金字塔，直接用真实采样绘制阶梯波形。

    CPU 引擎的实力

    请求 5 MSa/s 时实测 2.811 MSa/s，并把 200 kHz 的信号测为 200.06 kHz（误差 0.03%）——由于返回的是实测速率，时间轴依然正确。折算下来每个采样约 128 个时钟周期，主要开销在 PSRAM 写入。

    可以把 2.8 MSa/s 视为 CPU 引擎的上限。它是 PARLIO 不可用时的后备方案，不适合日常使用。

    如何称呼

    指标数值依据
    采样率80 MSa/s（8 通道同时）实测，边沿数与理论一致
    建议常用速率40 MSa/s 以下80 MSa/s 时复制中断占用 77%，余量不足
    最小可检测脉宽12.5 ns @ 80 MSa/s1 个采样周期
    已验证的输入频率19.44 MHz上述实测，更高频率未测量
    实用信号频率8–20 MHz保证 5–10 倍过采样时

    廉价逻辑分析仪标称「24MHz」时，这个 24 指的是采样率。按同样的说法，本机相当于 80MHz。但「80 MHz」容易被误读为「可以测量 80 MHz 的信号」，因此建议连单位一起写成 80 MSa/s。

    测量注意事项

    • 时间轴直接使用硬件分频值。用挂钟测量会因为包含启动与停止处理而偏长约 1%，该数值仅用于诊断显示。
    • 可测量的信号频率与采样率不同。要准确定位边沿需要 5–10 倍过采样，因此 40 MSa/s 适用于 4–8 MHz，20 MSa/s 适用于 2–4 MHz。
    • CPU 引擎的上限由循环速度决定，显示的是实测值。它是 PARLIO 不可用时的后备方案。

    浏览器模拟器

    无需实机即可运行 UI，并重新生成本手册中的所有截图。

    本手册中的所有截图都是把实机 UI 代码编译成 WebAssembly 后生成的，不是效果图。WaveformView、App、解码器、测量与 LOD 金字塔与固件使用完全相同的源码。

    工作原理

    基于 web-simulator-for-lvgl 的 M5GFX 兼容后端。该兼容层只提供像素、矩形与直线，因此 UI 所需的其余部分由 sim/ 补齐。

    • sim/sim_gfx.cpp — 文本绘制、圆角矩形与三角形。字体由 sim/tools/make_font.py 把 Consolas 位图化而来，字宽与 M5GFX 的 Font2/Font4 一致，因此标签不会溢出按钮。
    • sim/shim/ — M5Unified、Arduino、esp_heap_caps、esp_log 的最小桩实现。
    • sim/sim_sampler.cpp — 生成合成波形的 ISampler，场景中 I2C / UART / PWM / SPI 同时运行。

    UI 代码不直接使用 M5GFX，而是使用 include/gfx.h 中的 LaGfx，因此同一份源码可以同时用于固件与模拟器。

    构建

    生成可交互的 HTML：

    & ..\web-simulator-for-lvgl\lvgl-sim.ps1 build .

    会生成 build/lvgl-simulator/m5tab5-logic-analyzer.html，无需服务器即可直接在浏览器中打开。

    重新生成截图：

    pwsh sim/tools/build_shots.ps1

    把同样的源码编译成无界面的 Node 程序，用脚本化的触摸操作把 13 张图写入 docs/img/。由于是脚本驱动，每次运行得到的图片完全相同。

    模拟器发现的实机缺陷

    在截图过程中发现了两个同样存在于实机上的 UI 缺陷。

    • 点击面板的 Close 会留下光标 — 按钮处理完按下事件后，抬起事件穿透到了波形区。通过记录「按下已被消费」解决。
    • 点击后的第一帧绘制的是按钮的旧状态 — 按钮数组是在输入处理之前构建的。改为在绘制前重新构建。

    模拟器是 UI 预览，而不是开发板模拟器。PARLIO、microSD 与串口 API 都无法工作（Save 面板会如实提示浏览器中没有 microSD）。

    故障排查

    请先查看 Info 面板。

    现象需要确认的事项
    所有通道一直为高探头悬空，内部上拉在起作用。是否与被测电路共地？
    波形毛糙采样率不足。提高到信号的 5–10 倍；最小脉宽的测量值可作参考
    一直显示 UNTRIG触发条件过严。用 Trigger → Clear all 取消条件先看原始波形
    没有选中 PARLIO在 Info 中确认原因。若内部 RAM 不足则降低深度
    出现 OVERRUN RISK降低采样率，或把深度降到 191 kSa 以下以进入 direct 模式
    无法保存到 SD 卡确认 Save 面板显示的错误信息，并使用 FAT32 格式化的卡
    速率低于预期确认 ENG 是否变成了 CPU。该引擎的上限由循环速度决定
    API 没有响应是否碰了 DTR / RTS？碰了会进入引导程序。用 esptool --after hard-reset chip-id 恢复
    PlatformIO 工具安装失败是否从 Git Bash / MSYS 运行？请使用 PowerShell 或 cmd
